## 描述
claude -p 启动的会话在 session.start 时也会提交「[milestone] 恢复」提示：每次多跑一轮模型；且该轮 Claude 曾主动提出要把别的会话里正在执行的 task 标为完成。希望无界面会话不自动汇报。
## 验收标准
1. 有执行中目标时，claude -p "/ms-status" 只输出状态文字，不提交开场汇报，也不多跑一轮模型。
2. 有执行中目标时，终端交互会话（claude）开始时照常开场汇报。
3. 有执行中目标时，桌面版新会话照常开场汇报，而且只汇报一次。
4. 同一会话里之后又有界面接入（例如手机远程连接），不会再汇报一次。
5. claude plugin test 全过，并新增用例覆盖第 1、3、4 条的逻辑；validate 和 tsc 通过。
6. README 写明：无界面会话不开场汇报。
## 方案
会话开始时，如果是交互会话（session.start 的 isInteractive 为 true），或者 $.session.surfaces() 已有界面在显示，就照现在的做法汇报并请求打开面板；否则先不汇报，等第一次 session.attach 时汇报一次、打开面板，之后再有界面接入不重复。claude -p 从头到尾没有界面接入，所以永远不会汇报。
## 已定决策
autoResume 开关含义不变，设为 false 时任何会话都不汇报；不加「等几秒没有界面就放弃」之类的超时逻辑；若 T3 发现桌面版既非交互会话也不触发界面接入事件，停下与用户商量。
