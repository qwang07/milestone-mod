## Description
第一版有几项只在自动化测试或代码层面确认过，要在真实会话里验证，并把结论写回文档。
## Acceptance
1. 权限确认：默认权限模式下，第一次调用 milestone 工具时会不会弹出确认，有明确结论；如果弹，README 里写明可以加的允许规则。
2. 双会话同步：同一项目开两个会话，在其中一个里 /ms-new，另一个会话的面板在 5 秒内出现这个目标；测试用的目标随后 /ms-drop。
3. 命令清单：在新会话里问 Claude 下一步怎么做，它给出准确的命令名（先 /ms-focus 再 /ms-next），不编造不存在的命令。
4. 窄终端面板提示：有执行中的目标时，在不到 144 列宽的终端里重开会话，会弹出含 /ms-panel 的通知。
5. 结论写回文档：VERIFY.md 新增「验证记录」一节，第 1–4 项各一行结论；README 里与结论不符的说法改正。
## Approach
每项验证都由用户在真实会话里操作（开第二个会话、切权限模式、重开会话），Claude 给出具体步骤，再读文件和终端输出核对结果；结论确认后再改文档。
## Decisions
测试用的目标验证完就放弃，文件留在 .goals/ 不删除；提交 git 前先问用户；保留 T4（窄终端面板提示）；.serena/ 加入 .gitignore 不属于本目标，单独处理。
