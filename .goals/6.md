## Description
现在编号是全局自增的，同级子目标按编号排，等于按创建先后排。所以后补的子目标编号跳来跳去，顺序也没法按用户的意思排。编号只用作内部身份，面板和列表里不显示；新增明确的同级顺序，可以用自然语言让 Claude 调整，也可以在桌面和终端的面板里悬停出把手后拖拽。
## Acceptance
1. 新建的子目标排在同级最后；说「把 X 挪到 Y 前面」后，面板和 /ms-status 顺序随之改变并写入文件。
2. 面板、/ms-status、toast 不显示 #N；斜杠命令的目标参数可写编号或标题片段，多个匹配时列出候选。
3. 桌面和终端面板中悬停出现把手，可拖拽调整同级顺序，结果写入文件；手机和 VS Code 显示静态树。
4. claude plugin test、validate、tsc 全过；桌面 app 真实拖拽验证通过。
## Approach
目标 frontmatter 加 order 字段；同级按 order 排，没有 order 的旧文件按编号排在后面，不需要迁移；新目标的 order 为同级最大值加一。新增工具 move_goal({ id, before? })，只能在同级之间挪，挪动时重写这一组同级的 order。面板、/ms-status 和 toast 去掉 #N；新增 resolveRef，按编号或唯一的标题片段找目标。面板的目标树改由 Client 模块绘制：悬停显示 ⠿，按住拖动时画插入线、限同级，松开后 post 给 hooks，由 ui.message 走 move_goal 同一套逻辑；没有 Client 的界面画静态树。
## Decisions
拖拽只限同级，换父目标靠说话（本目标不做换父工具）。Claude 在聊天里以标题称呼目标；commit 信息和工具内部保留 #N。task 的 T1、T2 编号保留，它们本身就是连续的执行顺序。不新增调整顺序的斜杠命令。
