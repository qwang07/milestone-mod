# milestone 协议

项目的目标都在 `.goals/<id>.md`。issue、goal、milestone 都是「目标」；一个目标拆解时二选一：拆成子目标，或拆成 tasks。

## 总则

- **只通过工具修改目标**：`mcp__milestone__create_goal`、`plan_goal`、`start_task`、`finish_task`、`add_task`。不要用 Edit/Write 改 `.goals/` 下的文件，也不要用 TaskCreate/TodoWrite 管理这些目标的 tasks。读文件随意。
- 工具拒绝时，把原因原样告诉用户，不要绕过。
- 一个 task 一轮：每轮只推进一个 task，做完就结束本轮。

## 用户的命令

这些斜杠命令由用户输入，不占用你的回合；建议用户下一步时，用它们的准确名字：

| 命令 | 作用 |
|---|---|
| `/ms-new <标题> [--under <目标>]` | 记一个想法 |
| `/ms-plan <目标>` | 请你为目标找方案并拆解 |
| `/ms-focus <目标>` | 把一个「已计划」且拆成 tasks 的目标设为执行中 |
| `/ms-next` | 让你执行当前目标的下一个 task |
| `/ms-auto [n\|all]` | 连续执行 task，失败即停 |
| `/ms-skip` | 跳过当前 task |
| `/ms-add <描述>` | 请你提议追加一个 task |
| `/ms-done [目标]` | 确认目标完成 |
| `/ms-drop <目标>` | 放弃目标 |
| `/ms-status`、`/ms-panel` | 文字总览、打开面板 |

顺序：目标方案确认后是「已计划」，要先 `/ms-focus <目标>` 设为执行中，再 `/ms-next` 或 `/ms-auto` 执行。只有执行中的目标能开始 task。

## 新目标

用户提出一个新的问题或多步骤目标时：调用 `create_goal` 记下来（状态「想法」），告诉用户编号，并问是否现在找方案。简单的单步请求直接做，不进目标池。

## 找方案（`[milestone] 找方案 #N`，或用户要求为某目标出方案）

1. 阅读 `.goals/N.md` 和相关代码。这一阶段**只读**：不调用任何修改文件的工具。
2. 提出：描述、验收标准（可检验）、方案、已定决策，以及拆解建议——拆成 tasks（每个带标题和验收）还是拆成子目标。说明风险和待确认的问题。
3. 和用户多轮修改，直到用户**明确确认**。没有确认不调用 `plan_goal`。
4. 确认后调用 `plan_goal`。拆成 tasks 的，告诉用户用 `/ms-focus N` 设为执行中、再 `/ms-next` 开始；拆成子目标的，告诉用户对子目标用 `/ms-plan`。

## 执行（`[milestone] 执行 #N T<k>`）

1. `start_task` 标记开始。
2. 做这一个 task。将要执行删除、覆盖、强制推送、数据库迁移、对外发送等高风险操作时，先停下征得同意。
3. 对照这个 task 的验收逐条自检，给出证据（命令与输出）。
4. 自检通过 → `finish_task`。没通过 → 不调用 `finish_task`，说明失败在哪里。
5. 汇报：做了什么、验收结果、下一个 task 是什么；然后结束本轮。
6. 遇到计划没有涵盖的新情况，停下说明，不要擅自扩大范围。
7. 如果工具回复「全部 task 已结束」：对照目标的验收标准逐条汇报，提醒用户用 `/ms-done` 确认完成。

## 追加 task（`[milestone] 追加 task #N：…`）

提出 task 的标题和验收，等用户同意后调用 `add_task`。
